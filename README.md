# samwitte.com

The source for my personal site: [samwitte.com](https://samwitte.com).

It's plain static HTML and CSS. There's no build step and no framework. What's in
`src/` is exactly what gets published.

| URL | What | Where it lives |
| --- | --- | --- |
| `samwitte.com` | Landing page: two cards, PCB design or portfolio | `src/index.html` |
| `samwitte.com/portfolio/` | Timeline of work, projects, and school | `src/portfolio/index.html` |
| `samwitte.com/portfolio/...` | Write-ups linked from the timeline | `src/portfolio/{work,projects,school}/` |
| `samwitte.com/pcb/` | Freelance PCB design page and quote form | The separate [`samcwitte/pcb`](https://github.com/samcwitte/pcb) repo, whose source is the `dev/pcb-single-page` branch of this repo |

## Layout

```
src/
├── index.html            landing page
├── site.css              the whole site's styles (theme tokens match the /pcb page)
├── 404.html              not-found page; also forwards pre-2026 URLs to their new homes
├── CNAME                 custom domain for GitHub Pages; don't delete
├── Sam_Witte_Resume.pdf
├── public/               favicon and the landing page's card images
└── portfolio/
    ├── index.html        the timeline
    ├── work/  projects/  school/   write-ups
    └── images/           full-size images; thumbs/ holds the 640x480 timeline thumbnails
```

## Running it locally

```sh
yarn install    # once; the only dependency is push-dir, for publishing
yarn start      # serves src/ at http://localhost:8080
```

`/pcb/` links don't work locally because that page lives in another repo.

## Editing

**Timeline events.** In `src/portfolio/index.html`, copy an existing `<li class="event">`.
The comment above the timeline explains each field. Events go newest first, ordered by
when they ended. The `data-type` sets the colour and label: `job`, `freelance`, `internship`,
`research`, `teaching`, `project`, `hackathon`, or `coursework`. The colours are the
`--t-*` tokens at the top of `src/site.css`. The photo and the "Read more" link are both
optional.

**Write-ups.** Copy an existing page in the same folder, so the header, footer, and
relative paths (`../../site.css` and so on) stay right, then link to it from its timeline
event. When you change a write-up, update the "Last updated" line under its intro (both the
`datetime` attribute and the visible text).

**Images.** Keep them small. Use WebP where possible, about 1600 px wide for full-size
images and 640x480 for timeline thumbnails.

**Moving or renaming a page.** Add the old path to the map in `src/404.html` so old links
keep working.

## Publishing

`yarn push-gh-pages` force-pushes the contents of `src/` to the `gh-pages` branch, which
GitHub Pages serves at samwitte.com. Run it from this folder only. In the `-pcb`
worktree, the same command publishes the `/pcb` page to the `pcb` repo instead.

`push-dir` refuses to run with uncommitted changes, so always commit first. From the start:

1. **Work on a branch** (optional, but it keeps `main` matching what's live):
   ```sh
   git checkout -b dev/<something>
   ```
2. **Make the changes and preview them** with `yarn start`.
3. **Commit:**
   ```sh
   git add -A
   git commit -m "Describe the change"
   ```
4. **Publish:**
   ```sh
   yarn push-gh-pages
   ```
   This replaces the live site. GitHub Pages usually updates within a minute or two.
5. **Check the live site:**
   - `samwitte.com` loads;
   - whatever you changed looks right;
   - `samwitte.com/pcb` still works.
6. **Back up the branch, then merge it into `main`:**
   ```sh
   git push -u origin dev/<something>
   git checkout main
   git merge dev/<something>
   git push
   ```

For a quick fix straight on `main`, skip steps 1 and 6 and run `git push` after publishing.

## Branches

- `main`: the current site.
- `gh-pages`: what's published. It's generated by `yarn push-gh-pages`; never edit it by hand.
- `dev/pcb-single-page`: source for the `/pcb` page and the quote form's Cloudflare
  Worker (`worker/`). Checked out at `D:/Github/samcwitte.github.io-pcb`.
- `archive/mid-2026-refresh-wip` (local only): an abandoned Eleventy redesign, kept for
  reference.
